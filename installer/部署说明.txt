文件传输工具 —— 部署说明（给信息科）
=====================================

一、安装
  1. 双击「文件传输工具-x.y.z-安装包.exe」，需要管理员权限。
  2. 默认装到：C:\Program Files\文件传输工具
  3. 安装过程会自动做两件检查：
       · WebView2 运行时 —— 没有就用包里自带的离线安装器静默装上（1~2 分钟）；
       · .NET Framework 4.7.2+ —— 没有会弹一句提示，**不影响使用**（见第二节）。
  4. 装完可勾选「立即运行」。

  静默批量部署（域策略 / 批处理）：
      "文件传输工具-<版本>-安装包.exe" /S
      "文件传输工具-<版本>-安装包.exe" /S /D=D:\Apps\文件传输工具
  注意 /D 必须是最后一个参数，且路径不加引号。

  两种形态（内容一样，只差 WebView2 运行时）：
    · 完整版（约 231MB）：自带 WebView2 离线安装器，缺运行时的机器装完即用内嵌窗口。
    · 轻量版（约 24MB）：不含安装器。缺运行时的机器会走浏览器模式，功能完全一样。
      批量部署建议：先在一台机器上装完整版（把运行时装上），其余机器发轻量版。
  两者安装后的程序完全相同，可以互相覆盖升级。

二、两种界面模式（自动选择，不用配）
  双击启动后程序自检：
    · .NET 4.7.2+ 且 WebView2 都在  → C3：内嵌窗口（像普通桌面程序）
    · 任一缺失                      → C4：起本地服务，用系统默认浏览器打开
      界面内容完全一样，只是外壳不同；C4 只在 127.0.0.1 上监听。

  想强制某一档（排查时用）：
      文件传输工具.exe --c3
      文件传输工具.exe --c4
      文件传输工具.exe --tk          纯 Tk 窗口，完全不依赖 WebView2
  查看本机环境为什么落到某一档：
      python host_probe.py           （源码环境；打包版无此入口）

三、数据放在哪
  <安装目录>\data\        ← 安装时已预建，并给了 Users 修改权限
    .ftp_transfer_state.db        传输状态库（失败清单从这读）
    .ftp_transfer_ux.json         界面记忆（最近路径、窗口状态等）
    last_run.json                 上次定时任务的结果（界面顶部会显示这一条）
    .ftp_transfer_dl_parts\       下载续传的旁挂记录

  ⚠️ 配置跟着**机器**走，不跟账号：同一台机器上任何账号登录，看到的都是同一份
     配置与任务列表（信息科配一次，全科室轮班都能用）。
     **代价**：FTP 口令对该机的所有用户可见（文件本身不加密）。所以：
       · 优先用 FTPS（显式/隐式 TLS），别在明文 FTP 上放高权限账号；
       · 条件允许时给传输任务单独开一个受限账号，别用管理员账号。

  卸载**不会**默认删除 data\；要连数据一起清，见第六节。
  要彻底清除，手工删除该目录。

  多选与排序（2.6.1 起）：源列表支持单击选中、Ctrl 点加/减、Shift 点选一片；
  「－」一次删掉所有选中项，上移/下移对整块生效（块内顺序不变）。

四、定时任务（无头模式）
  界面里配好的定时任务由 Windows 计划任务唤起，命令是：
      文件传输工具.exe --run-task "任务名"
  **这个参数现在是支持的**（2.6.1 起）：进程不会弹窗口，跑完写 data\last_run.json，
  退出码按 config.SCHEDULE_EXIT_*（0 成功 / 4 起不来 / …），可在任务历史里看到。
  手动试跑一条：
      "C:\Program Files\文件传输工具\文件传输工具.exe" --run-task "每日备份"
  排查：data\logs\ 下每条任务一份日志；界面顶部会显示"上次定时任务：…"。

五、升级
  直接双击新版本安装包即可，不需要先卸载：
    · 会装到**原来的目录**（读注册表里记录的 InstallLocation），不会另起一份；
    · 先结束正在运行的旧实例，再替换文件；
    · 上一版的程序文件会被清掉，**data\ 全程保留** —— 配置、失败清单、
      最近路径、续传记录都不会丢；
    · 安装目录里你自己放的文件（临时扔个 exe、自己的说明）不会被删，升级
      不是"重置目录"；
    · 如果装的是比本机更旧的版本，会弹一句确认，不会静默降级。

六、卸载
  「设置 → 应用」里找「文件传输工具」，或运行安装目录下的 uninstall.exe。
  卸载会删掉：程序本体、文档、快捷方式、注册表卸载项。
  卸载会**问一句**要不要连配置数据一起删：
    · 选「否」（默认）→ 保留 data\，重装后接着用；
    · 选「是」→ 连 %LOCALAPPDATA%\文件传输工具 的兜底数据一起删。
  静默卸载默认保留数据；要连数据删干净：
      uninstall.exe /S /DELETE_DATA=1
  WebView2 运行时**不会**被卸载（系统共享组件，别的程序也可能用），
  如需移除请到「设置 → 应用」里单独卸载。

七、常见问题
  1) 双击后界面开在浏览器里，不是内嵌窗口
       → 说明 WebView2 或 .NET 缺失。用 --tk 可先顶着；
         要内嵌，手工运行安装目录下 vendor\MicrosoftEdgeWebView2RuntimeInstallerX64.exe。
  2) 安装时提示 WebView2 安装失败
       → 多为院内策略禁止安装系统组件。让管理员手动装一次即可，全机生效。
  3) 传输很慢、日志里反复出现「从头开始」
       → 服务器不支持 REST（加密通道下常见）。这属于服务器能力限制，
         日志里那三行探测结果（SIZE / MDTM / REST）能直接指明。
  4) 杀毒软件报警
       → 程序未做代码签名，且用 PyInstaller 打包，易触发启发式。
         本包已关闭 UPX 压缩以降低误报；仍报时请加白名单。
         汇报给厂商时附上第八节的 SHA256，便于他们确认是同一个文件。

八、完整性校验与杀软
  每个安装包旁边都有一份 SHA256SUMS.txt（与安装包同名目录内）。下发前后各核一次：
      certutil -hashfile "文件传输工具-<版本>-安装包.exe" SHA256
  与 SHA256SUMS.txt 里的值一致，说明传输过程没有损坏或被替换。

  没有代码签名意味着：Windows 会提示"未知发布者"，部分终端防护软件会拦。
  这不是程序有问题，而是没有证书（需要向 CA 购买，走医院采购流程）。
  过渡期的做法：
    · 在域策略/终端防护里把该安装包与安装目录加白；
    · 安装后核对安装目录里 exe 的版本号（右键属性 → 详细信息）应等于安装包标注的版本号。
