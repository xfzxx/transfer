## 一、这个程序是干什么的

**在本地硬盘和 FTP 服务器之间批量传文件**——可以整个文件夹递归地传，支持复制或移动，
支持断点续传，传了几百 TB 中断了也能接着传，不用从头再来。

主要能力：

- 本地 → 本地、本地 → FTP、FTP → 本地，任意组合
- 整目录递归，可按扩展名过滤（比如只传 `.dcm`）
- **复制**或**移动**（移动 = 传到目标后删掉源文件）
- **断点续传**：中断后重新开始，已传完的自动跳过
- **原子落盘**：先写 `xxx.part`，写完整了再改名成正式文件，避免出现"半个文件"
- **崩溃恢复**：程序被强杀/断电后重开，能接着上次的任务继续
- 有进度条、实时日志、暂停/停止/重传失败

## 二、怎么运行

### 方式 A：命令行启动（**推荐**，跑的一定是最新代码）

1. 打开 PowerShell
2. 输入下面两行（第一行是进入程序目录）：

```powershell
cd D:\AI\projects\transfer
python file_transfer.py
```

会弹出一个标题为「文件传输工具 v2.4」的窗口。

> **前提**：这台电脑装了 Python（含 tkinter，Windows 官方版自带）。
> 在 PowerShell 里敲 `python --version` 能打印版本号就说明可以。

### 方式 B：双击运行

直接双击 `file_transfer.py` 也可以，但**前提是 `.py` 文件已经关联到 Python**。
如果双击后闪一下就没了，说明没关联好，改用方式 A。

### 界面怎么用

| 位置 | 说明 |
|---|---|
| **源文件/文件夹** | 要传什么。**一个可以装好几项的列表**（见下面「怎么传多个文件夹」）。点「浏览」往里加；点「－」减掉选中的那一项；点右边的 **⚙** 设成 FTP 地址 |
| **目标文件夹** | 传到哪。点「浏览」选本地目录；点右边的 **⚙** 设成 FTP 地址 |
| **传输模式** | 选「复制」或「移动」 |
| **文件类型过滤** | 可选，如 `.dcm` 或 `.txt,.jpg`，留空表示全都传 |
| **并发线程数** | 同时传几个文件。**移动硬盘/机械硬盘建议填 1**；多线程只对本地传输有效 |
| **开始传输 / 暂停 / 停止 / 重传失败** | 四个操作按钮，按顺序解锁 |
| **传输日志** | 窗口下半部分，实时显示在干什么 |

**源或目标是 FTP 时**，先点那个 **⚙** 打开「FTP 连接设置」，填：

- 服务器地址、端口（默认 21）、用户名、密码
- 远程目录（例如 `/pub/data`）
- 填完先点 **「测试连接」**，通过了再点「保存」

保存后配置会记住，下次不用重填。

### 怎么传多个文件夹（**多源传输**）

「源文件/文件夹」那一格现在是**一个列表**，可以一次装好几个源。
一次点「开始传输」，程序会**一个源接一个原地传**（不是同时传，是排队传）。

#### 怎么加

点「**浏览**」，弹出三项：

| 菜单项 | 干什么 |
|---|---|
| **选择文件** | 加**一个或多个文件**（按住 `Ctrl` 多选 / 按住 `Shift` 连选） |
| **选择文件夹** | 加**一个文件夹**（里面的东西会递归全传） |
| **手工添加…** | 自己敲一个路径。**粘贴 FTP 地址时用这个**（比如 `ftp://user@host/pub/data`） |

> **注意**：「选择文件」和「选择文件夹」现在是**往列表里加**，不是**替换**。
> 旧版本里选一次就把原来那个顶掉了，现在会**追加**在下面。
> 想清空重来，就把列表里的项一个个用「**－**」减掉。

#### 怎么减

**先点一下列表里要减的那一项**（选中它），再点右边的「**－**」。
没选中就点「－」，它会提示你先选。

#### 列表装不下怎么办

源很多时（大约 4 个以上）列表会装满，**右边有一条滚动条**，拖它或者用**鼠标滚轮**
都能往下翻。加了几个源，列表右下角那条滚动条会显示当前看到的是哪一段。

> **源少的时候（1~3 个）滚动条拖了没反应**，这是正常的 —— 那时没有需要滚动的内容。
> 它**不会变灰**（这块界面库做不到），但拖了也不动，效果是一样的。

#### 传的时候是怎么排队的

* 开始传的时候日志里会写一行 **`启动 N 个源传输任务`**；
* 每传完一个源，写一行 **`[源 2/5] 完成：复制 12 个，跳过 3 个，失败 0 个`** ——
  方括号里是**第几个 / 一共几个**；
* 全部传完再写一行 **`全部完成：5 个源，共复制 60 个，跳过 3 个，失败 1 个`**；
* **每个源里的逐个文件**照旧实时打印，和以前一样。

**中途某个源不存在**（比如路径写错、U 盘拔了），那一行会显示
`[源 2/5] 不可用，跳过：D:\xxx`，然后**继续传下一个源**，不会整条卡住。

#### 出问题的时候

* **某个源里有文件传失败** —— 会在日志里存一份失败清单（和单源时一样），
  「重传失败」按钮重传的是**最后一个源**的失败文件；
* **点「停止」** —— **整条队列都停**，不会传完当前源又自己接着下一个；
* **想看哪个源慢** —— 直接看日志里 `[源 X/N]` 那几行分别花了多久（日志带时间戳）。
* **日志里出现 `⚠ …覆盖了源「…」的同名文件`** —— 两个源里有**同名**文件，
  后传的那个把先传的**换掉了**。这是**正常且有记录**的（不是报错）：
  日志里会**逐条**列出前 50 条，之后改成只写一行累计，例如
  `⚠ 跨源同名覆盖累计：已发生 2000 次跨源覆盖（详见 overwrites 表）`。
  **这样做是为了不让这些提示把别的关键日志顶出去** ——
  就算一次覆盖上万条，日志区也不会被占满。

  > **要看完整名单**：日志区只保前 50 条，**每一条**都在状态库里。
  > 查法见 **第七节 · 第 4 步**。

## 三、怎么打包成 exe

> ⚠️ **从 2026-09-19（界面美化）起，打包命令变了。**
> 以前那条手敲的 `pyinstaller --onefile --windowed --name ... file_transfer.py`
> **不能再用了** —— 它打出来的 exe **能生成、但一点开就崩**。
> 原因是界面美化用到的 `ttkbootstrap` 里有一部分东西是**运行时按名字动态取的**，
> PyInstaller 静态分析看不见，手敲命令不会把它们装进去。

### 正确做法（**用项目自带的 spec 文件**）

```powershell
cd D:\AI\projects\transfer
pip install pyinstaller ttkbootstrap pillow
python -m PyInstaller "文件传输工具.spec" --noconfirm --clean
```

**注意这里没有 `--onefile` / `--windowed` / `--name`** —— 三个参数都已经写在
`文件传输工具.spec` 里了，**再手敲一遍反而会互相打架**。

打包完成后，exe 在 **`D:\AI\projects\transfer\dist\文件传输工具.exe`**。
把这个 exe 复制到 `D:\AI\projects\transfer\`（覆盖旧的），就能双击用了。

> **`文件传输工具.spec` 是项目正式文件，不是中间产物，千万别删！**
> 它里面写着"要把 ttkbootstrap 的哪些东西装进 exe"。
> 删了它，下次只能手敲命令，而手敲出来的 exe 是坏的。
> （更早的说明里写着"spec 是自动生成的、可以删"—— **那句话从今天起作废。**）

> **打包前请先确认程序能正常跑**（能启动窗口、能测试连接）。
> 打包只是把能跑的东西装起来，不会修问题。

> **每次改完代码都要重新打包一次**，否则你双击的还是旧版本。
> 建议打包后看一眼 exe 的修改时间对不对。

打包过程还会在项目目录里生成 `build\` 和 `dist\` 两个文件夹，**都是中间产物**：

```powershell
Remove-Item build, dist -Recurse -Force
```

**只删这两个。** 删完记得把 `dist\` 里的 exe 先复制到项目根目录。

> **打包后的自检（30 秒）**：双击新 exe，确认界面是**白底、扁平**的现代样式，
> 不是以前的灰色立体按钮。如果界面是旧的灰样式，说明装进去的是旧代码；
> 如果点开直接闪退，八成是没按上面的 spec 方式打包。
>
> ⚠️ **"能打开"不等于"装的是新代码"。** 想知道包里到底是不是刚打完那一版，
> 看两个地方，**哪一个对不上都说明装错了**：
>
> 1. **窗口高度** —— 「传输日志」区下面应该还有一条明显的留白，不是紧贴着底边；
> 2. **源路径那一格** —— 应该是一个**框**（旁边有一条细滚动条），
>    不是旧版那种**单行输入行**。点「浏览 → 选择文件夹」应该能看到那一项**加进去**。

## 四、常见问题

### Q1. 连不上 FTP

按顺序排查：

1. **用程序自带的测试**：FTP 设置里点「测试连接」，它会直接告诉你错在哪
   （密码错、目录不存在、连不上服务器，报的错不一样）
2. **账号密码**：注意大小写；密码里如果有特殊符号，确认没被输入法改掉
3. **端口**：默认 21，但你单位服务器可能改过，问一下管理员
4. **远程目录**：填的目录必须**已经存在**，程序不会替你创建最外层目录
5. **防火墙 / 网络**：这台电脑能不能上到那台服务器？在 PowerShell 里试
   `Test-NetConnection 服务器地址 -Port 21`，`TcpTestSucceeded : True` 才算通
6. **被动模式**：多数 FTP 服务器需要被动模式，程序已默认处理；
   如果连得上但一列目录就卡住，多半是被动模式端口被防火墙挡了，找网络管理员

### Q2. 提示「已有任务在运行」/ 任务像被锁住了

这是**上一次的任务没有正常结束**留下的锁（程序崩溃、被强杀、或者直接关了窗口）。

**怎么办：等 30 秒，再点一次「开始传输」就行。**

原理：任务锁靠心跳维持，超过 **30 秒**没有心跳就自动作废，可以被新任务接管。
锁的作用是防止两个程序同时传同一批文件导致数据错乱，所以它宁可保守一点。

> 如果**经常**出现这个提示，说明程序在异常退出，别忽视——去看日志（见 Q3），
> 把崩溃时的日志内容留着。

### Q3. 日志在哪

有**两个地方**：

1. **界面上的「传输日志」区** —— 实时日志，程序关了就没了。
   **出问题时第一件事就是把它截图或复制下来。**

2. **失败清单文件** —— 文件名形如 `transfer_failed_20260918_143022.log`，
   只有在**确实有文件传输失败**时才会生成，里面列出失败的文件和原因。
   位置优先取 exe 所在目录；直接跑 `.py` 时是脚本所在目录；两者都取不到就用当前工作目录。

> 这个目录里堆了很多 `transfer_failed_*.log`，都是**以前跑测试时留下的**，
> 不是真故障。可以放心删掉。

3. **最可靠的是状态库**（见第五节）——它是结构化的，能查"哪次任务、传了多少、为什么结束"。
   日志文件会被覆盖或丢失，状态库不会。

### Q4. 传输过程中看到 `.part` 文件

**正常，不是出错。** 这是故意的保护机制：先把文件写成 `xxx.part`，
整个写完了才改名成正式名字。这样即使中途断电，目标目录里也**绝不会出现一个
看起来完整、实际只写了一半的文件**。

传输中断后残留的 `.part` 会在**下次任务启动时自动清理**（只清理超过 7 天的，避免误删别人正在写的）。

### Q5. 会不会重复传已经传过的文件？

**不会。** 程序按「文件名 + 大小 + 修改时间」判断文件是否已经传完，传完的会跳过，
可以直接重新开始而不用担心重传。这也是断点续传的实现方式。

> **多源这一版修掉了一个相关的毛病**：以前判断"传过没有"时**不看是哪个源**，
> 于是两个不同的源文件夹里如果有一个**同名、同大小、修改时间也一样**的文件，
> 第二个会被误判成"已经传过了"而**悄悄跳过**——日志还会说「全部完成」。
> 现在判断时把**源文件夹**也算进去了，两个源里的同名文件会各自老实传一遍。

### Q6. 点了「停止」之后，还能接着传吗？

能。用同样的源和目标重新开始，已经传完的会被跳过，从没传完的地方继续。

### Q7. 定时任务错过了时间，会补跑吗？

**新配的任务会补跑；在改动之前就已经配好的任务，要重新保存一次才会。**

「定时任务」是**第三个标签页**里配的东西（到点自动传一次）。它注册到的是 Windows
自己的「任务计划程序」，所以有两件事要分清：

* **到点了但机器关着 / 在睡眠** —— Windows 的默认值是「**错过就是错过，不补跑**」。
  本工具在注册任务时会把它改成「**下次可用时补跑一次**」。
  所以机器第二天开机之后，那次错过的传输会补上。
  ⚠️ 只补**一次**，不会把错过的每一天都补回来。
* **改动之前就已经配好的任务** —— 它们写进系统的那份注册信息里**还没有**这一条。
  **在那个标签页点一次「保存」（或用「全部重新注册」）就会补上**；
  在那之前，它们仍然按老规矩来 —— 错过就不补。
* 还有一条 Windows 的默认值本工具**没有改**：**「用电池时不启动」**。
  笔记本拔掉电源、光靠电池时，到点不会跑。

那个标签页底部的说明文字写的就是这几条。

## 五、状态库在哪

```
C:\Users\你的用户名\.ftp_transfer_state.db
```

（也就是 `~\.ftp_transfer_state.db`，`~` 代表你的用户主目录）

这是一个 SQLite 数据库，记录**每一次任务**和**每一个文件**的传输状态。
程序靠它在崩溃后恢复、靠它判断哪些文件已经传过。

里面有四张表：

| 表 | 存什么 |
|---|---|
| `meta` | 库的版本号等元信息 |
| `tasks` | **每一次传输任务**：源、目标、模式、状态、成功/跳过/失败数、结束原因 |
| `files` | **每一个文件**的任务与状态 |
| `remote_dirs` | 远端目录缓存，避免重复创建 |

**注意**：不要在用记事本/Excel 打开它，也不要在程序运行时手工改它。
要查内容请用下面第六节的方法（只读，安全）。

## 六、配置文件在哪

```
C:\Users\你的用户名\.ftp_transfer_config.json
```

（也就是 `~\.ftp_transfer_config.json`）

里面存的是**你在 FTP 设置窗口填过的连接信息**（服务器地址、端口、用户名、密码、远程目录）。
保存过一次就会记住，下次打开程序自动带出来。

它是一个纯文本 JSON 文件，可以用记事本打开看。**删掉它不影响传输功能**，
只是下次要重新填一遍 FTP 设置。

> 换电脑、或者想恢复出厂设置：直接删掉这个文件即可。

## 七、出问题时，第一步做什么

按这个顺序来，**不要一上来就重装或删库**：

### 第 1 步：看界面上的日志区

最后几行通常直接写着原因（连不上、权限不足、磁盘满……）。
**先截图**，这是最容易被忽略又最有用的东西。

### 第 2 步：查状态库里的 `tasks` 表

复制下面这一整行到 PowerShell，回车（**只读，不会改任何东西**）：

```powershell
python -c "import sqlite3,os; p=os.path.join(os.path.expanduser('~'),'.ftp_transfer_state.db'); c=sqlite3.connect(p); [print(r) for r in c.execute('SELECT task_id,status,src_root,dst_root,done_count,failed_count,end_reason,created_at FROM tasks ORDER BY task_id DESC LIMIT 10')]"
```

它会打印**最近 10 次任务**，每行 8 个字段：

```
task_id, status, 源目录, 目标目录, 成功数, 失败数, 结束原因, 创建时间
```

重点看两个字段：

- **`status`** —— 任务状态
- **`end_reason`** —— **结束原因，这一列最有用**。正常跑完和异常中止，这里写的不一样。

如果任务卡在"进行中"但其实没在跑，那就是 Q2 说的残留锁，等 30 秒即可。

### 第 3 步：查某个具体文件传没传

下面这条是**搜文件**用的。它里面有两处 `dcm`（在 `\'%dcm%\'` 里），
**把这两处都换成你要找的关键词**再回车（比如换成 `patient001`）：

```powershell
python -c "import sqlite3,os; p=os.path.join(os.path.expanduser('~'),'.ftp_transfer_state.db'); c=sqlite3.connect(p); [print(r) for r in c.execute('SELECT filename,status,dst_path FROM files WHERE filename LIKE \'%dcm%\' LIMIT 20')]"
```

> ⚠️ **一定要把两处 `dcm` 一起换掉**，只换一处会报错。
> 嫌麻烦的话，请直接搜**能不能用更短的关键词**，不要改动命令的其他部分 ——
> 尤其是 `\'`、`%` 这些符号，动一个就跑不起来。

### 第 4 步：查哪些文件被别的源覆盖过

多源传输时，两个源里有同名文件，后传的那个会**换掉**先传的那个
（日志里会写 `⚠ …覆盖了源「…」的同名文件`）。
日志区只保留**前 50 条**，**完整名单在状态库的 `overwrites` 表里**：

```powershell
python -c "import sqlite3,os; p=os.path.join(os.path.expanduser('~'),'.ftp_transfer_state.db'); c=sqlite3.connect(p); [print(r) for r in c.execute('SELECT filename,old_src_root,new_src_root,dst_path FROM overwrites ORDER BY rowid DESC LIMIT 20')]"
```

每行 4 个字段：

```
文件名, 被覆盖的那份原来属于哪个源, 覆盖者来自哪个源, 目标路径
```

### 第 5 步：还是搞不定

**停下来，别自己删东西。** 把这三样凑齐再找人看：

1. 日志区的截图（或复制的文字）
2. 第 2 步那张 `tasks` 表的输出
3. 你做了什么操作、当时期望它做什么

> **千万不要**在没搞清楚之前删 `~\.ftp_transfer_state.db`。
> 删了它，程序就"忘记"了哪些文件已经传过 —— 不会丢数据，但会从头重传一遍，
> 几百 TB 的规模下这个代价很大。
